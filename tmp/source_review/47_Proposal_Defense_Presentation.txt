The TradeoffsProductivity gains come with a critical tension
3
Security Vulnerabilities
- Developers may accept insecure AI-generated code, introducing security flaws into production systems.
Verification Failure
- Developers may trust suggestions too quickly and skip proper review or testing.
Increased Debugging Cost
- Incorrect AI outputs can waste time and effort during debugging and troubleshooting.
Productivity Loss
- Excessive skepticism can prevent developers from benefiting from useful AI assistance.
False Confidence
- Confident-sounding AI responses can make developers believe incorrect solutions are correct.

Research GapWhat Is Still Missing
9
"Limited empirical understanding of how different cognitive modes affect developer trust and verification behaviour 
when working with LLM-based coding assistants."
01
Parallel but Disconnected Streams
Cognitive mode studies and trust calibration studies have been conducted separately. No prior work integrates both 
into a single empirical framework.
02
Unmeasured Attentional Drop
Theory predicts developers become less vigilant in fast-flow states, but this has not been directly measured in 
software engineering contexts.
03
Indirect Trust Proxies
Existing studies rely on acceptance rates and self-reports rather than measuring cognitive state alongside trust 
behaviour simultaneously.
This study bridges the two streams by co-observing cognitive mode and trust behaviour within the same experimental session.

Theoretical FoundationTwo Theories That Frame This Research
10
Dual-Process Theory  ·  Kahneman (2011)
System 1  —  Fast, Automatic
Intuitive pattern recognition. Developers in familiar 
tasks accept AI suggestions rapidly with minimal 
conscious deliberation.
System 2  —  Slow, Deliberate
Analytical reasoning. Developers encountering 
unfamiliar problems slow down, scrutinise suggestions, 
and validate outputs carefully.
→  Predicts that cognitive mode shapes how critically AI 
output is evaluated.
Grounded Copilot Theory  ·  Barke et al. (2022)
Acceleration Mode
Developer knows the approach. AI acts as intelligent 
autocomplete. Suggestions are accepted rapidly through 
pattern recognition with minimal prompting effort.
Exploration Mode
Developer faces uncertainty, unfamiliar APIs, new libraries, 
complex bugs. AI is used for discovery. Prompts are 
deliberate, outputs are compared and tested.
→  Developers dynamically switch between modes 
depending on task familiarity.

Core ConceptResearch Questions (RQs)
11
RQ1 Do developers accept AI suggestions more quickly and without checking in acceleration mode compared to exploration 
mode?
RQ2 How does a developer's conﬁdence in a suggestion compare to actual correctness, and does this gap change between 
modes?
RQ3 What veriﬁcation behaviours do developers exhibit in each mode, and how do they affect the number of errors accepted?
RQ4 Can cognitive mode be identiﬁed from IDE signals ( acceptance latency, prompting patterns, or edit frequency ) ?
RQ5 Do trust miscalibration patterns differ across SE task types (completion, API exploration, bug repair) when controlling for 
mode?

Expected Contributions

Behavioural Evidence Across Modes
First study to directly compare trust miscalibration rates between 
acceleration and exploration modes using co-measured cognitive state and 
behavioural logs.
Theoretical
Integration of Two Frameworks
Bridges Kahneman's Dual-Process Theory with Barke et al.'s Grounded 
Copilot model, establishing a unified lens for trust calibration research.

verification habits, supporting responsible AI adoption in professional
