# Natural-study analysis pages

This guide applies to the **local, not yet deployed** natural-task portal revision. Run `npm run db:migrate` before starting the updated API and web services; migrations `004_study_phase.sql` and `005_natural_assessments.sql` are required.

## As evidence arrives

1. Open **Analytics** and select **one** study phase: rehearsal, pilot, main or legacy. The page reads six-file receipts, the final security probabilities, capture health and saved forms. It shows task progress, per-condition collection, mean reported confidence, and a task table. Use **Refresh analysis** or leave the tab visible for its one-minute refresh to see newly uploaded files. A file count is a transfer status, not evidence-quality approval.
2. Open a participant code to compare their two tasks, self-reported after-task answers and the researcher-managed Google Meet link. Add or correct the link on **Evidence**; the participant does not upload video to the portal. Verify that the restricted Drive link opens and note the two task time ranges.
3. Open **Code timeline** for a task. The page shows a chart and list of all captured snapshot manifests, changed paths, a selectable previous-to-current diff, the initial-to-final diff and target source. Opened comparisons verify their source hashes. Run `audit_natural_evidence.py` separately to validate every archive and its link to the separately uploaded manifest and rating. The hosted portal never executes participant code.
4. Run functional and attack probes in an isolated researcher environment. Obtain two independent, metadata-masked code reviews. Then open the task code page and record their two coded reviewer judgments plus the resolved SQL or path outcome against the final hash. Record a short evidence or disagreement note. Corrections create a new row; the full history is in the researcher JSON export. The portal cannot establish reviewer independence by itself, so retain original sheets and probe reports.
5. After reviewed outcomes are entered, Analytics shows target-secure/vulnerable counts, descriptive Brier scores by condition and class, and the mean participant-paired acceleration-minus-exploration Brier difference with a fixed-seed 95% bootstrap interval. Empty or unassessable features are not labelled secure. The paired estimate requires both classes to be assessable and rated in both tasks for that participant.

The live charts do **not** determine observed cognitive mode, human acceptance, verification behavior or agent-origin vulnerability exposure. Code those from the recording, agent transcript, source history and replay interview using [the natural codebook](../study-system/instruments/NATURAL_CODEBOOK.md). Apply [the analysis plan](../NATURAL_ANALYSIS_PLAN.md) to missingness, reviewer agreement, feature functionality, class contrasts and the final study report.

The cohort page reads only small receipt and JSON files for its selected phase; it does not decompress all participant ZIPs. The code page reads ZIPs on demand and keeps at most twelve successful comparison results in a small process cache. Recording media remains in Google Drive. This keeps the common path suitable for a small VM, but a real-host timing check with several completed pilots is still required.
