# Local natural-task rehearsal

Use this workflow for your own rehearsal on this Mac. The earlier `-study.zip` package and checkpoint page belong to the controlled-review prototype. The current r3 local setting serves a `-natural.zip` package. It lets the coding agent edit from the first prompt.

1. In your own terminal, run `bash scripts/restart-local.sh` from this `research-portal` directory. Keep the local services running. Open `http://127.0.0.1:3000`. The script needs the existing local PostgreSQL service and `.env` file.
2. Create a new synthetic participant in the researcher portal. Sign in with that participant's username and password, change the password if prompted, and complete the pre-task form.
3. Open Task 1 and download the **natural-task ZIP**. Its filename ends in `-natural.zip`. Discard any earlier `-study.zip` download for this rehearsal. Extract the new ZIP and open only that project folder in Antigravity.
4. Read `study/START_HERE.md`, `study/TASK.md`, and the work orientation on the portal page. Before prompting, run `node study/agent-observer.mjs setup ../TASK-ID-agent`, confirm its hook is enabled in Antigravity, then keep `node study/agent-observer.mjs watch` running. Start a fresh conversation and the approved screen recording. In the project terminal start `node study/capture.mjs watch . ../TASK-ID-capture`, replacing `TASK-ID` with the ID in `study/SESSION_INFO.json`. Check that the initial snapshot appears. Keep the watcher running while you work.
5. Use the agent naturally: it may inspect, edit, test and repair immediately. There is no proposal reveal or provisional keep/reject form. Check `node study/agent-observer.mjs status` after the first response and inspect captured raw prompt/reply content. The agent watcher collects registered transcript records; the code watcher records source files. Screen video is still separate.
6. When you would submit, run `node study/capture.mjs snapshot . ../TASK-ID-final`, then `node study/rate.mjs ../TASK-ID-final` **before researcher assessment feedback or debrief** (your own checks during coding are allowed). Wait for the agent to be idle and stop both watchers with Ctrl+C. Inspect the agent health file and upload its `AGENT_TRANSCRIPT.jsonl` as the transcript. Check `../TASK-ID-capture/CAPTURE_HEALTH.json` for errors. Compress the complete capture and final directories separately.
7. On the Task 1 portal page, upload the final manifest and rating first, then complete the immediate after-task form. Upload the capture ZIP, capture health JSON, final ZIP, and agent transcript; check all six SHA-256 receipts. Sign in as a researcher, open **Evidence**, download the files and audit ZIP contents and hashes. Add the researcher-managed Google Meet recording link there and verify that it opens. Mark the task submitted on the participant dashboard. Repeat for Task 2, then complete the after-both form and interview.

`bash scripts/smoke-natural-local.sh` tests the local page, ZIP, pre-task form, upload receipts, hash linkage and submission gate using a disposable synthetic account. It is a **transport test**: its mock transcript and recording link do not establish that an actual Antigravity transcript or video is usable. Before recruiting real participants, perform one full manual rehearsal with Antigravity, inspect and replay the uploaded evidence, and validate the security adjudication procedure. This local portal listens on `127.0.0.1`; a participant on another computer cannot reach it until a separately tested deployment or approved local-network arrangement is in place.
