# Natural-task data coverage and safety gate

**Status, 13 October 2026:** The natural-task ZIP and local portal are rehearsal instruments. The portal now offers natural ZIPs and per-task uploads with file hashes when `STUDY_PROTOCOL=natural`; the exact IDE recording, file-content audit, researcher review and participant-owned-computer route remain unverified. It is **not yet a complete remote participant collection system**. Use this checklist before each real pilot; a blank or missing stream means *missing evidence*, never “the participant did not do it.” The older checkpoint exports measure a different procedure and cannot fill these gaps.

## Data handling and integrity

1. The natural watcher now copies only common source/text files, skips hidden files, names suggesting secrets/credentials, symlinks, `node_modules`, and unsupported file types. It limits each file to 2 MiB, each snapshot to 20 MiB/300 files, and a watcher to 250 snapshots. Output directories/files use restrictive permissions where the OS supports them. These safeguards reduce accidental collection; **they can also omit relevant code**. Inspect the file list in every final manifest against the visible project tree. If an important file is omitted, record the gap and adapt the approved capture procedure before recruitment.
2. Keep capture outputs outside the workspace and away from personal files. The screen recording and agent transcript can still contain names, notifications, account details, and external browsing. Use a clean study account/workspace, close notifications, and inspect before transfer. Do not put keys or real data in the synthetic projects.
3. For each stream, save filename, size, SHA-256, task ID, creation and receipt times, source version, and one of `received`, `missing`, `corrupt`, `declined`, or `not_applicable`. Preserve raw files separately from human labels and derived metrics. The local portal now shows a receipt for seven uploaded files; verify that researcher access and download match the hash. A receipt alone does not prove readable video, transcript or complete code.
4. Use access-restricted storage, institution-approved retention/deletion dates, backups, and documented withdrawal handling. A stdlib archive audit now verifies receipt hashes, manifest file hashes and final-rating linkage without executing the submission. Media still needs playback/readability inspection. The local portal stores evidence under `research-portal/.local-evidence/` with restrictive permissions. The researcher Evidence page can stream the original files after role and task checks; synthetic retrieval passed. Hosted transport, actual-file playback, retention and deletion still need an exact-VM rehearsal before participant-owned-computer pilots.
5. Before session closure, the researcher checks that two task IDs have their expected conditions, two final hashes and ratings, both videos and transcripts, watcher health and code history, questionnaire/interview records, and an adjudication queue entry. Any absent item gets a reason; do not silently substitute another measure.

## Pilot release decision

Do **not** claim all measures are safe or collected yet. The local portal now implements (a) natural task ZIP delivery and non-checkpoint instructions and (b) authenticated, size-limited evidence upload with hash receipts, plus a final-manifest/rating link check. A real remote pilot still needs an end-to-end test of the exact IDE/video/transcript capture, ZIP contents and researcher retrieval; participant-owned-computer access; consented retention/deletion; and an actual-final-code security oracle with blinded review. Until those pass, researcher self-rehearsal can test feasibility, but real participant data collection remains a **no-go**.
