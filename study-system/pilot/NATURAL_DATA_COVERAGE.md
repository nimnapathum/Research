# Natural-task data coverage and safety gate

**Status, 13 October 2026:** The natural-task ZIP is a local rehearsal instrument. It is **not yet a complete hosted participant collection system**. Use this checklist before each real pilot; a blank or missing stream means *missing evidence*, never “the participant did not do it.” The older checkpoint portal and its exports measure a different procedure and cannot fill these gaps.

## Minimum linked record for each of the two tasks

| Evidence and derived measure | Collection method | Present state and required check |
| --- | --- | --- |
| Pseudonymous ID, project, assigned condition, task order | `SESSION_INFO.json`; researcher allocation | Generated in each natural ZIP. Verify the portal assignment matches; never infer observed mode from condition. |
| Role, development/agent experience, JavaScript and security familiarity | Before-task questionnaire | Old portal form exists but directly cues SQL/path concepts. Natural wording and hosted saving are **not implemented**. |
| Host/OS, Antigravity/model/Node versions, screen scale, input device, interruptions | Researcher session log | **Manual and incomplete** until entered for every task. |
| Task/recording start and stop, common clock marker | Screen recording and researcher log | **Manual**. Check audio/video playback, time display and clock offset against code snapshot timestamps. |
| All visible prompts, replies, agent edits/tools and agent waiting time | Official Antigravity export plus screen recording | **Not captured by the natural kit**. Export must be checked on each exact Antigravity version/OS. Hook logs from the old checkpoint ZIP are not part of this natural ZIP. |
| Code evolution, changed files, final exact code and content hash | `node study/capture.mjs watch` and `snapshot` | Local 2-second snapshots and final manifest **implemented**; brief edits may be missed. Confirm initial, at least one changed snapshot when changes occur, final hash, `CAPTURE_HEALTH.json` without errors, and file coverage. |
| Final security probability for SQL and path, reasons, willingness to submit, stated agent reliance | `node study/rate.mjs` | Local JSON tied to final hash **implemented**. Record before feedback and check both answers, hash and time. **No hosted receipt yet.** |
| Agent-origin vulnerable change exposed, human inspection/repair/retention, final security | Video/transcript, snapshot lineage, blinded review and attack tests | **Human coding and final-code oracle not yet built** for free-task outputs. Do not count an unobserved vulnerability as rejected, accepted or repaired. |
| Security checks before and after provisional retention; ordinary tests; scanner results | Video/transcript and coded command/output evidence | **Manual coding only**. Command invocation without inspected outcome is not a completed security check. “Provisional retention” must be inferred from observed continuation; mark ambiguous timing `unclear`. |
| Observed acceleration, exploration, mixed or unclear episodes | Two coders using prompts, video and replay interview | **Planned, not automatic**. Duration, cursor motion and prompt length may support description, not serve as mode labels. |
| After-task difficulty, familiarity, known-next-step and option-seeking; replay interview | Short after-task form and audio/video interview | Questions drafted in the rehearsal runbook; **natural hosted form and recording receipt absent**. |
| Pointer speed, clicks, scrolling, typing cadence, focus/navigation, explicit acceptance latency | Optional validated host telemetry/video | **Not guaranteed** in natural kit. Browser cannot observe Antigravity pointer. Old optional `pynput` recorder has OS/permission limits and global scope; do not treat missing as zero. There is no native accept click in free agent editing, so do not report the old checkpoint decision latency as natural acceptance latency. |

## Data handling and integrity

1. The natural watcher now copies only common source/text files, skips hidden files, names suggesting secrets/credentials, symlinks, `node_modules`, and unsupported file types. It limits each file to 2 MiB, each snapshot to 20 MiB/300 files, and a watcher to 250 snapshots. Output directories/files use restrictive permissions where the OS supports them. These safeguards reduce accidental collection; **they can also omit relevant code**. Inspect the file list in every final manifest against the visible project tree. If an important file is omitted, record the gap and adapt the approved capture procedure before recruitment.
2. Keep capture outputs outside the workspace and away from personal files. The screen recording and agent transcript can still contain names, notifications, account details, and external browsing. Use a clean study account/workspace, close notifications, and inspect before transfer. Do not put keys or real data in the synthetic projects.
3. For each stream, save filename, size, SHA-256, task ID, creation and receipt times, source version, and one of `received`, `missing`, `corrupt`, `declined`, or `not_applicable`. Preserve raw files separately from human labels and derived metrics. Make a server receipt visible to the participant after upload and verify that researcher download matches the hash.
4. Use access-restricted storage, institution-approved retention/deletion dates, backups, and documented withdrawal handling. The current local watcher does **not** provide portal transport, encryption, retention or deletion controls. Those must be implemented and tested in the hosted service.
5. Before session closure, the researcher checks that two task IDs have their expected conditions, two final hashes and ratings, both videos and transcripts, watcher health and code history, questionnaire/interview records, and an adjudication queue entry. Any absent item gets a reason; do not silently substitute another measure.

## Pilot release decision

Do **not** claim all measures are safe or collected yet. A hosted natural pilot needs: (a) natural task ZIP delivery and non-checkpoint instructions; (b) authenticated, size-limited upload of code history/final/rating/video/transcript with hash receipts and private storage; (c) final-snapshot security ratings in the portal or a verified import; (d) per-task coverage audit; (e) Antigravity plus recording rehearsal on the participant OS; and (f) an actual-final-code security oracle and blinded review. Until those pass end to end, the researcher-only rehearsal can test feasibility, but real participant data collection through the hosted portal is a **no-go**.
