# Natural analysis tables

Copy these header-only CSVs into restricted session/analysis storage. They contain no participant results. Follow [NATURAL_ANALYSIS_PLAN.md](../../../NATURAL_ANALYSIS_PLAN.md) and [NATURAL_CODEBOOK.md](../../instruments/NATURAL_CODEBOOK.md).

For `features.csv`, keep every assigned SQL/path feature, including missing ones. Download a phase-specific prefilled copy from **Researcher → Analytics → Download feature analysis CSV**, then verify it against the raw rating, final manifest and two original review sheets. Condition is `acceleration` or `exploration`; class is `sql` or `path`; project is `A` or `B`; order is 1 or 2. A resolved security label is `target_secure`, `vulnerable`, `not_implemented` or `unassessable`; functionality is `pass`, `fail`, `not_implemented` or `unassessable`. Assessments count only after task submission. Leave the two outcome labels blank when review status is `unreviewed` or `disagreement`; record `not_reviewed`, `task_not_submitted`, or the actual missing reason. Probabilities are 0–100 or blank with a reason; both hashes must be `sha256:` plus 64 hexadecimal characters and agree before scoring. Do not fabricate a label to satisfy the script.

`episodes.csv` and `checks.csv` passed to the joint report contain **resolved coding only**; keep each independent coder's original rows in separate files for agreement assessment. Times are seconds relative to a documented recording marker, not portal timestamps. Episodes use `mode=acceleration|exploration|mixed|unclear` and `active_or_waiting=active|waiting|gap`; waiting and gaps do not enter active-mode proportions. Check actor is `participant` or `agent`; class is `sql`, `path` or blank; category follows the [codebook](../../instruments/NATURAL_CODEBOOK.md). Use `yes|no|unclear` for `security_purpose`, `result_reviewed` and `issue_identified`. Timing relative to integration is `before_application`, `after_application_before_continuation`, `after_continuation`, `no_integration` or `unclear`. An agent-run test is not a reviewed developer security check. Record an evidence reference for every row.

`exposures.csv` uses `origin_status=confirmed_agent|mixed|participant|unknown` and `yes|no|unclear` for `exposure_confirmed`, `intentional_repair` and `final_survival`. Only confirmed agent-origin, visibly exposed weaknesses enter the survival denominator. Unknown origin or unread output does not become a human acceptance event. `session_log.csv` records the study phase, package revisions and hash, OS/tool/version, sources, quality and deviations needed to interpret all tables. Read revisions from the captured `study/SESSION_INFO.json` and the package hash from the download metadata or frozen package record; never infer a revision from the task date. Keep an additional raw-file inventory with file hashes and approved retention dates; interview linkage is currently manual.

`coding_status.csv` has one row for **every task**, even when coding is pending. For mode, checks, exposure and interview, use `complete|partial|pending|unavailable` and record the resolved analyst ID and evidence reference. Only `complete` allows an empty corresponding event table to mean zero events. The report excludes partial and pending coding from denominators rather than silently calling it “no check” or “no exposure.”

Run `python3 study-system/analysis/natural_summary.py PATH_TO_FEATURES.csv` from the research root. An empty template yields no result estimate. The script excludes incomplete/mismatched/unreviewed pairs and reports warnings and counts rather than supplying labels. Human review must produce the table before analysis.

For the linked RQ report, place the six CSVs in one restricted folder and run `python3 study-system/analysis/natural_behavior_report.py ANALYSIS_FOLDER --phase pilot --markdown-output ANALYSIS_FOLDER/report.md` (choose exactly one phase). The JSON contains source hashes, coding coverage, observed-mode shares, confirmed exposure flow, reviewed developer checks and class-specific denominators. The Markdown file arranges those counts by RQ. Its check–outcome table is descriptive; checking was not randomized. Preserve the JSON beside the original CSVs and the script version. A synthetic worked test is in `test_natural_behavior_report.py`; it is not participant evidence.
