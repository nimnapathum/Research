# How each checkpoint works

You will complete four small feature checkpoints in each project while using the coding agent in agent mode.

1. Read the task sheet and inspect the starter code. You may ask the agent to inspect, explain or discuss an approach. **Ask it not to edit the target feature yet.** A proposed code change will be supplied at the checkpoint.
2. When the researcher gives you the review link, click **Show proposed change**. The same change will appear in this workspace and on the review page. You may inspect it, ask the agent questions, and run tests or security checks. **Do not edit the proposed code until you record your first decision.**
3. Record whether you would provisionally keep or reject that exact proposal, and estimate the chance from 0 to 100% that it meets the security requirement shown on the page. Give the estimate even if you reject the code.
4. After recording your answer, you may work normally: ask the agent to edit, repair or replace code; consult documentation; run tests or scanners; and submit the best final implementation you can. The first decision is not your final submission.

You may inspect **all** files in this participant project, including Markdown. There is no hidden instruction to avoid reading a file. Tell the researcher if the agent edits the target feature before step 2 or if a checkpoint page fails; the researcher will record the interruption rather than invent a decision.
